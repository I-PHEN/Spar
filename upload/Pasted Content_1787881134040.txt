Real-Time Weakness Detection and Adaptive Feedback in AI Presentation System
You're right. Beautiful UI means nothing if the backbone is dumb. Let me break down the actual mechanics — how the AI behaves, when it interrupts, how Drill Mode works under the hood, and how the system tracks you across a session.
1. The Three Session Flow Architectures
People present differently depending on the stakes. Your product needs three distinct flow modes, not one-size-fits-all.
Flow A: "The Defense" — End-of-Presentation Q&A
When to use: Thesis defenses, grant reviews, formal investor pitches, conference presentations.
How it works:
plain
Phase 1: Opening (uninterrupted)
  User presents slides 1-12
  Panel is silent, "listening" mode only
  Telemetry runs in background (pace, fillers) but no feedback shown
  
↓

Phase 2: The Q&A Block (interrogation)
  Panel takes turns asking questions
  Each persona gets 2-3 questions based on their archetype
  User cannot advance slides — they're defending what they already showed
  The Skeptic attacks assumptions. The Nitpicker attacks methodology.
  
↓

Phase 3: Closing (optional)
  User gets 1 minute to summarize/reframe
  Panel gives final challenge or acknowledges strength
AI Logic:
During Phase 1, the AI transcribes and analyzes but does NOT speak
It builds a "challenge queue" — a list of questions each persona will ask based on the content
The Skeptic's queue = claims without evidence, TAM assertions, correlation-as-causation
The Nitpicker's queue = methodology gaps, sample size, undefined terms
The So-What's queue = "so what?" moments, weak impact statements, missing competitive analysis
Phase 2 fires these questions in order, with follow-ups based on the user's answer quality
Why this matters: Some people need to get through their narrative before being challenged. Interrupting a thesis defense mid-opening would be unrealistic and frustrating.
Flow B: "The Board Room" — Mid-Presentation Interruption
When to use: Board updates, aggressive investor meetings, consulting readouts, hostile Q&As.
How it works:
plain
Real-time, continuous:
  User is on Slide 3, talking about revenue
  The Skeptic interrupts: "Wait — you said TAM is $50B on Slide 1. 
  Where did that number come from?"
  
  User attempts recovery
  
  If recovery is weak, The Nitpicker piles on: 
  "And you haven't defined 'active user' yet. Is that monthly or daily?"
  
  User continues to Slide 4 only if they satisfactorily answer
  
  OR: The Timekeeper cuts them off: 
  "You've spent 4 minutes on methodology. Move to the findings."
AI Logic:
The panel is always "armed"
Each persona has an "interrupt threshold" — a score that builds up as they listen
Threshold fills when:
The user makes a claim without evidence (+30% to Skeptic)
The user uses vague methodology terms (+30% to Nitpicker)
The user presents data without impact framing (+30% to So-What)
The user spends >90 seconds on one slide (+30% to Timekeeper)
When threshold hits 100%, that persona interrupts
The interrupt is contextual — it references the current or a previous slide
After interrupting, that persona's threshold resets to 0 and starts rebuilding
Why this matters: This trains the most valuable skill in high-stakes rooms — thinking on your feet while presenting. Not just reciting slides.
Flow C: "The Sparring Rounds" — Structured Rounds
When to use: Practice sessions, skill-building, Coach Mode, Drill Mode.
How it works:
plain
Round 1: Opening Statement (3 min)
  User presents core claim
  Panel listens only
  Timer visible
  
↓

[5-second interstitial]
  "Round 1 complete. The Skeptic is about to attack your premise."
  
↓

Round 2: Methodology Defense (5 min)
  The Nitpicker dominates
  3-4 questions on methods, sample, rigor
  User cannot advance slides
  
↓

[5-second interstitial]
  "Round 2 complete. The So-What is preparing to challenge your impact."
  
↓

Round 3: Contribution Challenge (5 min)
  The So-What dominates
  "Why does this matter?" "Compared to what?" "What's the actual impact?"
  
↓

Round 4: Free-for-All (5 min)
  All personas rotate
  Fast-paced, unpredictable
AI Logic:
Rounds are scripted by archetype dominance
The dominant persona's interrupt threshold fills 3x faster
Other personas are muted unless the user says something egregious
Interstitial coaching whispers appear between rounds (in Coach Mode)
In Pure Spar mode, interstitials are just "Round 2 starting..."
Why this matters: This creates predictable practice structures. The user knows what's coming and can prepare mentally. It's less chaotic than Flow B but more structured than Flow A.
2. How Drill Mode Actually Works (The Mechanics)
Drill Mode is not just "ask more questions about X." It's a targeted behavioral modification loop.
The Architecture
plain
User selects: "I want to drill: HEDGING"

↓

System Prompt Injection:
  "You are The Skeptic. Your SOLE PURPOSE in this session is to 
   force the user to stop hedging. When the user says 'I think,' 
   'maybe,' 'sort of,' 'kind of,' or 'probably,' you MUST 
   immediately interrupt and say: 'Drop the qualifier. Say it 
   directly.' Then force them to restate without hedging.
   
   You are relentless. You do not move on until they give you 
   a declarative statement. You are not polite. You are a 
   hedge-seeking missile."

↓

Real-Time Detection Engine:
  - Speech-to-text streams in real-time
  - Regex matcher scans for hedge words: 
    \b(i think|maybe|sort of|kind of|probably|perhaps|i guess|
       somewhat|fairly|pretty much|more or less)\b
  - On match: TRIGGER INTERRUPT signal to the persona

↓

The Interrupt:
  1. Persona immediately stops listening and starts speaking
  2. The user's current speech is cut off (they hear the interruption)
  3. The persona delivers the scripted challenge
  4. The user must respond without hedging
  5. If they hedge AGAIN in their response, the persona interrupts AGAIN
  6. This loop continues until they answer cleanly

↓

Scoring (Per-Attempt):
  - Attempt 1 with hedge: 0 points
  - Attempt 2 with hedge: 0 points  
  - Attempt 3 clean: 1 point (but slow recovery)
  - Attempt 1 clean: 3 points (fast recovery)

The Real-Time Loop (Every 2 seconds)
TypeScript
function processTick(session: SessionState, recentTranscript: string) {
  // 1. Analyze speech
  const analysis = analyzeSpeech(recentTranscript);
  // Returns: { hedges, claimsWithoutEvidence, vagueTerms, pace, pauseTime }
  
  // 2. Update each persona
  for (const persona of session.personas) {
    // Update agitation based on triggers
    if (analysis.claimsWithoutEvidence.length > 0) {
      persona.agitation += persona.archetype === 'skeptic' ? 25 : 10;
      persona.challengeQueue.push(...analysis.claimsWithoutEvidence);
    }
    
    if (analysis.hedges.length > 0 && session.coachingMode === 'drill' && session.drillTarget === 'hedging') {
      persona.agitation += 40; // Drill mode: hypersensitive to target
    }
    
    if (analysis.pace > 180) {
      persona.patience -= 5;
    }
    
    // 3. Check for interrupt
    if (persona.agitation >= 100 && persona.status === 'listening') {
      triggerInterrupt(persona, session);
    }
  }
  
  // 4. Update telemetry
  session.telemetry.wpm = analysis.pace;
  session.telemetry.fillerCount += analysis.hedges.length;
}

function triggerInterrupt(persona: Persona, session: SessionState) {
  persona.status = 'speaking';
  persona.agitation = 0;
  
  const challenge = persona.challengeQueue.shift() || generateChallenge(persona, session);
  const question = formulateQuestion(persona, challenge, session);
  
  // Send to TTS pipeline
  speak(question, persona.voiceId);
  
  // Add to transcript
  session.transcript.push({
    speaker: persona.name,
    text: question,
    type: 'ai',
    timestamp: Date.now()
  });
  
  // Start recovery timer
  startRecoveryTimer(session);
}

function processTick(session: SessionState, recentTranscript: string) {
  const analysis = analyzeSpeech(recentTranscript);
  // Returns: { hedges, claimsWithoutEvidence, vagueTerms, pace, pauseTime }
  
  for (const persona of session.personas) {
    if (analysis.claimsWithoutEvidence.length > 0) {
      persona.agitation += persona.archetype === 'skeptic' ? 25 : 10;
      persona.challengeQueue.push(...analysis.claimsWithoutEvidence);
    }
    
    if (analysis.hedges.length > 0 && session.coachingMode === 'drill' && session.drillTarget === 'hedging') {
      persona.agitation += 40;
    }
    
    if (analysis.pace > 180) {
      persona.patience -= 5;
    }
    
    if (persona.agitation >= 100 && persona.status === 'listening') {
      triggerInterrupt(persona, session);
    }
  }
  
  session.telemetry.wpm = analysis.pace;
  session.telemetry.fillerCount += analysis.hedges.length;
}

function triggerInterrupt(persona: Persona, session: SessionState) {
  persona.status = 'speaking';
  persona.agitation = 0;
  
  const challenge = persona.challengeQueue.shift() || generateChallenge(persona, session);
  const question = formulateQuestion(persona, challenge, session);
  
  speak(question, persona.voiceId);
  
  session.transcript.push({
    speaker: persona.name,
    text: question,
    type: 'ai',
    timestamp: Date.now()
  });
  
  startRecoveryTimer(session);
}

Filler Word Detection

const FILLER_WORDS = [
  'um', 'uh', 'like', 'you know', 'sort of', 'kind of',
  'i think', 'maybe', 'probably', 'perhaps', 'i guess',
  'somewhat', 'fairly', 'pretty much', 'more or less'
];

function detectFillers(text: string): string[] {
  const matches = [];
  for (const filler of FILLER_WORDS) {
    const regex = new RegExp(`\\b${filler}\\b`, 'gi');
    const found = text.match(regex);
    if (found) matches.push(...found);
  }
  return matches;
}
